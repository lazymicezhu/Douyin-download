# DouyinLite · 抖取

English · [简体中文](README.md)

A lightweight native iPhone app for downloading Douyin media and querying Douyin data through TikHub. Built with SwiftUI, with no third-party dependencies or self-hosted backend. The current app version is **2.1**; the app interface is in Simplified Chinese.

## Features

- **Video downloads**: Paste a share message or URL, choose from the qualities actually returned by the API, and save to Photos or export a file. Supports H.264 and HEVC sources.
- **Original-quality sources**: Fetch the original source separately. Copies saved to Photos are remuxed without re-encoding and receive a full-frame-rate playback marker, preserving source resolution, frame rate, and audio/video samples. The untouched source can also be exported. The playback marker requires iOS 18+ support; Photos on iOS 17 may ignore it.
- **Photo posts and Live Photos**: Preview and select images, copy captions, and create Live Photos locally or save still images and separate motion clips.
- **Data queries**: 20 endpoints covering creators, posts, comments, search, trends, music, collections, livestreams, Xingtu creators, and keyword trends. Includes manual pagination, ID copying, and JSON export.
- **Account and history**: View normal balance, free credits, platform daily usage, and local request history with estimated charges based on balance changes.

Available quality and content depend on the source post and TikHub's response. The app does not upscale the source or remove text embedded by its creator.

## Requirements

| Purpose | Requirement |
| --- | --- |
| Building | macOS, full Xcode 16 or later with an iOS 18+ SDK, and Python 3; command-line tools must point to that Xcode installation |
| Running | An iPhone with iOS 17 or later |
| Resolving media and querying data | Your own [TikHub account](https://user.tikhub.io/) and API Key; paid endpoints require a usable balance or eligible free credits |
| Device installation | A valid signing certificate and provisioning profile, or your own development team configured in Xcode |

Only Apple system frameworks are used. No CocoaPods or Swift Package dependencies need to be installed. An API Key is not required to build the app.

## Clone and build

```sh
git clone https://github.com/lazymicezhu/Douyin-download.git
cd Douyin-download
./scripts/build.sh
```

The script regenerates the Xcode project and builds the device app with one build job, producing **`dist/DouyinLite-unsigned.ipa`**. It stages the build in a temporary directory to support source paths containing spaces or colons. `build/` and `dist/` contain local output and are excluded from version control.

For debugging in Xcode, open `DouyinLite.xcodeproj`, select the `DouyinLite` scheme, and configure your Team and an available Bundle Identifier under Signing & Capabilities. The project is generated by `scripts/generate_project.py`; update the generator when making persistent project-setting changes.

To build the simulator app only:

```sh
./scripts/build.sh --simulator
```

This produces `build/Simulator/DouyinLite.app` without launching a simulator. See the [development guide](docs/development.md) for more details.

## Install and configure

1. Import your locally built unsigned IPA into a signing tool, such as 全能签, and sign it with a valid certificate and provisioning profile before installation. An unsigned IPA cannot be installed directly; its validity depends on the signing credentials. Alternatively, install from Xcode after configuring signing.
2. Open **抖取 → 账户 → API Key 与配置文件** (Account → API Key and configuration). Enter your Key manually, or copy it and choose “粘贴并保存” (Paste and Save).
3. You can also import an `.env` / `.txt` text file containing the following configuration, or paste the full configuration text without removing its prefix:

```dotenv
TIKHUB_API_KEY=your_tikhub_api_key
```

Replace the placeholder with your own Key. Once saved, the Key is stored in the device Keychain and can be replaced or removed in the app.

**Optional local configuration**: Copy [.env.example](.env.example) to `.env` in the project root and enter your Key. If that file exists, the device build script copies it to `dist/TikHub.env` and `dist/TikHub.txt` for transfer to your iPhone and import. Building also works without `.env`. These configuration files contain your private Key and are ignored by Git; they are not included in the IPA.

## Usage

1. Paste a full share message or Douyin URL into the Download tab and tap “获取作品” (Fetch Post). Paid requests show a quote and require confirmation before being sent.
2. Choose a video quality or select photos and a Live Photo save mode, then save to Photos or export files. The first save requests permission to add items to Photos.
3. “获取原画” (Fetch Original) and “链接失效？重新获取” (Expired Link? Fetch Again) are separate requests with fresh price checks. Repeating the same link in one session normally reuses the existing result.

Live Photo export produces a paired JPEG and MOV. Use Save to Photos to add a native Live Photo directly to the iPhone library. If pairing fails, export separate assets without resolving the post again. Temporary media is removed when switching posts or on the next launch; saved and exported files remain.

## Costs and privacy

- Business requests obtain an endpoint quote first. Paid requests require confirmation, and requests stop if a valid quote is unavailable. Each confirmation covers one request; paid endpoints are not automatically retried, and each next page needs separate confirmation.
- Quotes show the base price in USD. Discounts and free credits may change the actual debit; TikHub's bill is authoritative. A request that has already been sent may be charged even if cancelled, unsuccessful, or unable to return usable content.
- Downloading returned media, switching between existing qualities, local processing, saving, and exporting do not call paid resolution endpoints.
- Account balance and daily usage refresh only after their endpoint prices have been verified as zero. Automatic queries pause if pricing changes or cannot be checked. Balance refreshes roughly every 30 seconds in the foreground, with throttling for repeated checks.
- Local per-request charges are **estimates from balance changes**, not itemized platform bills. Concurrent account use, top-ups, delayed settlement, or missing snapshots can leave a charge unverified. Platform daily usage includes other tools using the same account.
- The API Key is stored in the device Keychain and sent only to `api.tikhub.io`; media downloads do not include it. Query input is sent to TikHub, and media is downloaded from the returned URLs.
- Request history is grouped by a hash of the Key and stored locally, without the Key, request parameters, or full responses. Uninstalling the app deletes its local history. Exported JSON and media files remain under your control.

## Development and verification

```sh
./scripts/test.sh
```

By default, this runs the **offline CoreTests checks** without credentials or paid API calls. It does not execute every test file under `tests/`. See the [development guide](docs/development.md) for quality, billing, and Live Photo checks. The manual `--live` / `--inspect` modes read your local `.env`, access the real API, and may incur charges directly; they are outside the routine offline checks.

Signing, device installation, Photos import, Live Photo presentation, and high-frame-rate playback still require device checks. Existing results and outstanding checks are listed in the [verification notes](docs/verification.md).
